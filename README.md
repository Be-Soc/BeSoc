# besoc

Координационный репозиторий экосистемы Be-Soc. Собственного кода
нет: besoc координирует спецификации, компоненты (пины
git-сабмодулей) и кросс-спеки уровня экосистемы.

## Компоненты

**База:**

- **BeSoc/PoSoc** — база экосистемы: децентрализованная сеть
  доверия и её транспортный слой (соцграф-транспорт записей,
  идентичности/ключи, L0, базовое доверие). Спецификация
  протокола — в сабмодуле ([PoSoc/specs](PoSoc/specs/index.md)).
  Отдельные приложения (см. ниже) используют BeSoc/PoSoc как
  сетевую основу.
- **quinn**, **rust-libp2p** — форки upstream Rust-проектов
  (QUIC и libp2p) как транспортные библиотеки;
  upstream-документация используется как reference-документация.

**Приложения (потребители BeSoc/PoSoc):**

- **BeSoc Base App** — базовое приложение с собственным UI
  (механизмы PoSoc: L0/генезис, FRIEND-связи, consent-объекты
  и гранты, ключи и восстановление, доверие); обычный клиент
  Local API узла, без привилегий в Node Runtime; первый
  потребитель Local API — приложения-домены потребляют тот же
  Local API.
- **CloDem** — приложение «облачной демократии»: собственные
  иерархии уровней власти, механизмы делегирования и доверия,
  голосования, советы, должности.
- **GplVote** — приложение голосования (организация gpl-vote);
  спецификаций пока нет.
- **Chat** — приложение обмена сообщениями (в планах).

Единица распространения — distribution bundle: один пакет
магазина (Node Runtime + BeSoc Base App + выбранные UI-модули
доменов, например «BeSoc + CloDem»); «установка функции» —
активация домена внутри bundle. Active Node Runtime на
устройстве — ровно один, все UI-модули живут в его
Host-процессе; bundle — не superapp: нет монолитного UI и общих
прикладных прав, общий только Runtime с его минимальными
пермишенами. Разграничение базы и надстройки на примере CloDem —
[specs/posoc-cdem.md](specs/posoc-cdem.md); модель состояния
приложений и bundle-модель —
[specs/app-state-model.md](specs/app-state-model.md).

## Целевая платформа

- **Основная цель** — мобильные устройства: Android и iOS.
- **Вспомогательные компоненты** — допускаются на Linux-серверах:
  только bootstrap/relay-инфраструктура сообщества, не
  обязательный элемент узла пользователя.
- **Ядро системы** — Rust (кроссплатформенное, общее для Android
  и iOS через FFI).
- **UI** — Kotlin (Android; на iOS — через Kotlin Multiplatform
  либо нативный слой, детали — предмет спецификации UI).
- **Сетевой транспорт** — libp2p, основной протокол — QUIC
  (соответственно, сабмодули-форки `rust-libp2p/` и `quinn/`).
- **Сетевая часть — отдельный фоновый сервис без UI.** Весь
  PoSoc/CloDem-транспорт и логика ядра живут в background-сервисе;
  UI-приложения взаимодействуют с ним только локально (IPC/API на
  устройстве). Целевая аудитория — пользователи только с телефоном,
  без своих серверов: узел сети работает исключительно на
  устройстве. На Android — foreground service с локальным API;
  на iOS аналога отдельного процесса нет — роль сервиса выполняет
  extension/фоновый режим (ядро in-process), узел фактически
  онлайн только при активном использовании приложения; это
  фиксируется как известное платформенное ограничение, транспорт
  PoSoc обязан его терпеть (эпизодическое присутствие узлов —
  норма, а не исключение).

## Методология

Spec-driven development (уровень 1: спецификация до кода) +
test-driven development (уровень 2: тесты до реализации).
Спецификации размещаются как в корневом besoc (`specs/` —
уровень экосистемы), так и в компонентах-сабмодулях.
Индекс — [specs/index.md](specs/index.md).
