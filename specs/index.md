# Индекс спецификаций экосистемы Be-Soc

besoc — координационное ядро экосистемы Be-Soc и связующая часть между компонентами: собственные спецификации уровня экосистемы размещаются здесь, в `specs/`, а спецификации компонентов — в репозиториях-сабмодулях. Этот файл — точка входа для поиска спецификаций и документации по экосистеме.

Сабмодули закреплены (pinned) за конкретными коммитами; все пути и описания ниже действительны для этих коммитов и пересматриваются при обновлении пинов.

## Спецификации besoc

besoc — ядро системы и связующая часть между компонентами; собственные спецификации уровня экосистемы размещаются здесь, в `specs/`, и индексируются в этом разделе.

Методология разработки: spec-driven development на 1-м уровне (спецификация до кода) и test-driven development на 2-м уровне (тесты до реализации). Спецификации могут размещаться как в корневом besoc (уровень экосистемы), так и в репозиториях компонентов-сабмодулей.

Спецификации уровня экосистемы:

- [specs/posoc-cdem.md](posoc-cdem.md) — двухслойная архитектура «CloDem поверх PoSoc» (v0.2): PoSoc — базовая транспортная подсистема (соцграф-транспорт записей, идентичность/ключи, L0, базовое доверие), CloDem — прикладная надстройка «облачной демократии» с собственными механизмами (иерархии уровней власти, матричное делегирование, tally и пороги, советы, должности, инициативы, мониторинг обещаний). Разграничение ответственности слоёв (использует PoSoc как есть / механизм CloDem / стыковочное соглашение), единственное требование к PoSoc (перевозка прикладных записей), несовместимости, разрешаемые внутри слоя CloDem, и открытые вопросы.
- [specs/app-state-model.md](app-state-model.md) — модель состояния приложений «один узел — общее хранилище — много приложений» (v0.3): единый Rust-рантайм узла (безразличный к Host-профилю), два Host-профиля (Android foreground service / iOS in-process), BeSoc Base App — базовое приложение с собственным UI пользовательских механизмов PoSoc (L0, FRIEND, consent, ключи, доверие), клиент того же Local API без привилегий в Node Runtime, полнота Local API проверяется силами BeSoc Base App; общее хранилище состояний с доменами и доменными тегами, изоляция и междоменный доступ через consent/FRIEND/MEMBER_OF механики PoSoc, синхронизация всех доменов общим транспортом (anti-entropy, eventual consistency как норма), единый Local API (один IDL, uniffi-биндинги Kotlin/Swift), жизненный цикл, целостность БД, миграции доменных схем, квоты и GC-горизонты; distribution bundle — единица распространения (один пакет: Runtime + Base App + UI-модули доменов, установка функции = активация домена, один Active Node Runtime на устройство, bundle — не superapp). Единственное требование к PoSoc — унаследованное T1.

## PoSoc

Полноценная спецификация протокола PoSoc (v0.13): разделы Concept (введение, принципы и модель угроз, архитектура, связи, L0, иерархия, доверие, защиты, параметры, ограничения, ZKP-roadmap) и Implementation (форматы записей, криптография, эталонные реализации, транспорт), плюс глоссарий.

- [specs/index.md](../PoSoc/specs/index.md) - мастер-индекс спецификации PoSoc (v0.13)
- [docs/posoc-concept.md](../PoSoc/docs/posoc-concept.md), [docs/posoc-implementation.md](../PoSoc/docs/posoc-implementation.md), [docs/posoc-plain.md](../PoSoc/docs/posoc-plain.md) - зеркальная документация

PoSoc (Proof of Social) — децентрализованная сеть доверия без инфраструктуры, позволяющая каждому участнику отличать реальных людей от ботов и виртуальных аккаунтов в пределах наблюдаемого им компонента социального графа; гарантии — условные и вероятностные, в терминах стоимости атаки.

Статус: полноценная спека (v0.13).
