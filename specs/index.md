# Индекс спецификаций экосистемы Be-Soc

besoc — координационное ядро экосистемы Be-Soc и связующая часть между компонентами: собственные спецификации уровня экосистемы размещаются здесь, в `specs/`, а спецификации компонентов — в репозиториях-сабмодулях. Этот файл — точка входа для поиска спецификаций и документации по экосистеме.

Сабмодули закреплены (pinned) за конкретными коммитами; все пути и описания ниже действительны для этих коммитов и пересматриваются при обновлении пинов.

## Спецификации besoc

besoc — ядро системы и связующая часть между компонентами; собственные спецификации уровня экосистемы размещаются здесь, в `specs/`, и индексируются в этом разделе.

Методология разработки: spec-driven development на 1-м уровне (спецификация до кода) и test-driven development на 2-м уровне (тесты до реализации). Спецификации могут размещаться как в корневом besoc (уровень экосистемы), так и в репозиториях компонентов-сабмодулей.

Спецификации уровня экосистемы:

- [specs/posoc-cdem.md](posoc-cdem.md) — двухслойная архитектура «CloDem поверх PoSoc» (v0.2): PoSoc — базовая транспортная подсистема (соцграф-транспорт записей, идентичность/ключи, L0, базовое доверие), CloDem — прикладная надстройка «облачной демократии» с собственными механизмами (иерархии уровней власти, матричное делегирование, tally и пороги, советы, должности, инициативы, мониторинг обещаний). Разграничение ответственности слоёв (использует PoSoc как есть / механизм CloDem / стыковочное соглашение), единственное требование к PoSoc (перевозка прикладных записей), несовместимости, разрешаемые внутри слоя CloDem, и открытые вопросы.
- [specs/app-state-model.md](app-state-model.md) — модель состояния приложений «один узел — общее хранилище — много приложений» (v0.4): единый Rust-рантайм узла (безразличный к Host-профилю), два Host-профиля (Android foreground service / iOS in-process), BeSoc Base App — базовое приложение с собственным UI пользовательских механизмов PoSoc (L0, FRIEND, consent, ключи, доверие), клиент того же Local API без привилегий в Node Runtime, полнота Local API проверяется силами BeSoc Base App; общее хранилище состояний с доменами и доменными тегами, изоляция и междоменный доступ через consent/FRIEND/MEMBER_OF механики PoSoc, синхронизация всех доменов общим транспортом (anti-entropy, eventual consistency как норма), единый Local API (один IDL, uniffi-биндинги Kotlin/Swift), жизненный цикл, целостность БД, миграции доменных схем, квоты и GC-горизонты; distribution bundle — единица распространения (один пакет: Runtime + Base App + UI-модули доменов, установка функции = активация домена, один Active Node Runtime на устройство, bundle — не superapp); мультиустройственность — норма (PoSoc v0.14: устройство владеет device-ключом и действует от имени identity-ключа владельца). Единственное требование к PoSoc — унаследованное T1.
- [specs/transport-identity.md](transport-identity.md) — транспортная идентичность экосистемы Be-Soc (v0.1): контракты транспортного уровня, введённые разделением ключей PoSoc v0.14 — identity-ключ человека (единственный участник протокола, выводится из seed) и device-ключ устройства (транспортный, вне протокола: локальная случайная генерация, класс ключей libp2p/PeerId). Сертификат устройства (подпись identity-ключа: pk_device, epoch, expiry), реестр устройств (подписанный список device-ключей с монотонным epoch; распространяется транспортом PoSoc как прикладная запись, eventual consistency), пошаговый контракт аутентификации соединения (подпись + активная FRIEND по правилу маппинга + сверка epoch сертификата с известным реестром), отзыв устройства новым epoch реестра и окно отзыва, seed-восстановление (seed-изоляция; старые device-ключи остаются в реестре до явного отзыва), relay/bootstrap-узлы только с device-ключами без identity-ключа.

## PoSoc

Полная спецификация протокола PoSoc (v0.14): все разделы в едином файле specs/spec.md — назначение, принципы и модель угроз, архитектура, связи, базовые группы L0, эмерджентная иерархия, потребление доверия, защитные механизмы, криптография и объёмы, параметры, ограничения, ZKP-roadmap, эталонные реализации и глоссарий.

- [specs/spec.md](../PoSoc/specs/spec.md) — спецификация протокола PoSoc (v0.14), единый файл

PoSoc (Proof of Social) — децентрализованная сеть доверия без инфраструктуры, позволяющая каждому участнику отличать реальных людей от ботов и виртуальных аккаунтов в пределах наблюдаемого им компонента социального графа; гарантии — условные и вероятностные, в терминах стоимости атаки.

Разделение ключей (v0.14): identity-ключ человека — единственный участник протокола (пара Ed25519, детерминированно выводимая из seed; только identity-ключи фигурируют в записях и подписывают их); device-ключ — транспортный ключ устройства вне протокола (сертификаты устройств и реестры устройств — транспортный уровень экосистемы: [specs/transport-identity.md](transport-identity.md)).

Статус: полноценная спека (v0.14).
